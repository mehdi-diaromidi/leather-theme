# پروتکل تحویل و بازبینی (Cursor ↔ ناظر از طریق گیت)

## چرخه‌ی هر فاز
1. **شروع:** از `main` به‌روز شاخه بساز: `git checkout -b phase/N-<name>`. فقط وقتی `docs/review/phase-(N-1)-APPROVED.md` روی `main` هست.
2. **کار:** commit های کوچک و معنادار، پیشوند `phase N:`. فقط محدوده‌ی همین فاز؛ کار فاز بعد یا refactor بی‌ربط ممنوع.
3. **خودبازبینی:** چک‌های بخش ۵ نقشه‌راه را اجرا کن؛ گزارش‌ها را در `qa/reports/phase-N/` بگذار (ignore است؛ خلاصه‌ی اعداد در handoff بیاید).
4. **گزارش تحویل:** `docs/handoff/phase-N.md` (قالب پایین) را بنویس و `docs/PROGRESS.md` را به‌روز کن.
5. **Push و توقف:** `git push -u origin phase/N-<name>` سپس **متوقف شو** و منتظر بازبینی بمان. چیزی را به `main` merge نکن.
6. **بازبینی (ناظر):** `git fetch && git diff main...phase/N-<name>`، اجرای چک‌ها، مقایسه‌ی ظاهری، و نوشتن `docs/review/phase-N-R<k>.md`.
7. **اصلاح:** هر یافته را با شناسه‌اش (`F1`, `F2`…) در commit جدید رفع کن؛ در handoff بخش «Fix log» را به‌روز کن؛ push؛ توقف.
8. **تایید:** وقتی بازبینی هیچ یافته‌ی blocker/major باز ندارد، ناظر `phase-N-APPROVED.md` می‌نویسد. مدیر پروژه شاخه را به `main` merge می‌کند. سپس فاز بعد.

## قواعد رفتار ایجنت
- **حدس نزن.** ابهام = سؤال در handoff (بخش «پرسش‌ها»)، نه فرض پنهان.
- **چیزی را «انجام‌شده» نگو مگر تست شده.** تست‌نشده را صریحاً بنویس.
- کاری خارج از مرز فاز یا تغییر در سایت زنده/پلاگین فعال بدون تایید مدیر ممنوع است.
- اگر یافته‌ای را قبول نداری، دلیل فنی را در handoff بنویس؛ بی‌صدا نادیده نگیر.
- هر استثنا از parity فقط با تایید مدیر در `PARITY-EXCEPTIONS.md`.

## قالب `docs/handoff/phase-N.md`
```md
# فاز N — <نام> — تحویل R<k>
- شاخه / آخرین commit:
## انجام‌شده (مطابق DoD فاز، بند به بند)
- [x] ...
## فایل‌های مهم تغییر‌کرده
- مسیر — توضیح یک‌خطی
## نحوه‌ی تست (دقیق، قابل تکرار)
1. ...
## نتایج QA
- phpcs: ... | چک ممنوعه‌ها: ... | diff: صفحه/عرض → درصد
## تست‌نشده / ریسک‌ها
- ...
## پرسش‌ها از مدیر / ناظر
- ...
## Fix log (از R2 به بعد)
- F1: چه کردم — commit
```

## قالب `docs/review/phase-N-R<k>.md` (نوشته‌ی ناظر)
```md
# بازبینی فاز N — دور k
نتیجه: ❌ نیازمند اصلاح | ✅ تایید
## یافته‌ها
### F1 [blocker|major|minor] — عنوان
- محل: path:line
- مشکل:
- چرا مهم است (parity/امنیت/استاندارد/لایسنس):
- راه رفع:
- روش راستی‌آزمایی:
## موارد تاییدشده
## دستور بعدی به ایجنت
```

## معیار شدت
- **blocker:** اختلاف ظاهری/رفتاری قابل‌مشاهده، حفره‌ی امنیتی، کد/نام Woodmart، نقض لایسنس، فاتال PHP.
- **major:** ناسازگاری با استاندارد (WPCS/escape/i18n/RTL)، regression عملکردی، توکن‌های هاردکد، نبود حالت تعاملی.
- **minor:** تمیزی کد، نام‌گذاری، کامنت/مستند.
فاز تنها وقتی تایید می‌شود که blocker و major باز نداشته باشد.
