# نقشه‌راه تبدیل bagllet.ir به قالب اختصاصی تجاری

> مخاطب: ایجنت Cursor. ناظر: بازبین (از طریق گیت). مدیر پروژه: مهدی.
> این فایل منبع حقیقت است. هر ابهامی را اینجا یا در `docs/handoff/` ثبت کن؛ حدس نزن.

## ۰. هدف و قواعد طلایی

**هدف:** قالب وردپرس مستقل (بدون Woodmart) که ظاهر و رفتار سایت فعلی bagllet.ir را **بدون ذره‌ای تغییر** بازتولید کند، و بعداً قابل فروش در بازارهای فارسی‌زبان (راست‌چین و مشابه) باشد. خریدار باید بتواند ظاهر و محتوا را (لوگو، رنگ‌های مجاز، فونت، هدر/فوتر، متن‌ها، تصاویر، بخش‌های صفحه اصلی) بدون کدنویسی سفارشی کند.

**قواعد غیرقابل‌مذاکره:**
1. **برابری ظاهری (Parity):** مرجع = سایت زنده‌ی فعلی (خط پایه‌ی فاز ۱). هر تفاوت پیکسلی/رفتاری باگ است، مگر در `docs/PARITY-EXCEPTIONS.md` با تایید مدیر ثبت شده باشد.
2. **صفر کد Woodmart:** از Woodmart فقط برای **اندازه‌گیری** (computed style، breakpoint، رفتار) استفاده کن. هیچ خط CSS/JS/PHP/تصویر/آیکن آن را کپی نکن؛ همه‌چیز را از صفر و به سبک خودمان بنویس. کلاس‌های `wd-`، `xts-`، `woodmart` در خروجی قالب ممنوع‌اند (بخش ۵ را ببین).
3. **صفر وابستگی سخت به Elementor** برای هدر، فوتر، فروشگاه، محصول، سبد، تسویه، حساب کاربری. Elementor فقط برای محتوای صفحه‌ی اصلی (با ویجت‌های پلاگین همراه) اختیاری است.
4. **توکن‌های «شناسنامه استایل»** (`شناسنامه استایل bagllet.ir.md`) تنها منبع رنگ/فونت/فاصله/radius هستند. هیچ hex یا px پراکنده در CSS مجاز نیست؛ همه از CSS variables.
5. **استاندارد وردپرس:** WPCS، escape دیر/sanitize زود، nonce+capability، i18n، RTL، PHP ‏7.4 تا 8.3، آخرین وردپرس و ووکامرس. کد نباید مبهم‌سازی/رمزگذاری شود (شرط بازارها).
6. **لایسنس دارایی‌ها:** هر فونت/تصویر/آیکن/کتابخانه‌ی داخل قالب باید لایسنس قابل‌ثبت و قابل‌فروش داشته باشد (`docs/LICENSES.md`). فونت IRANYekan بسته‌ی تجاری **داخل zip فروش نمی‌رود** (بخش ۱.۳).
7. **هر فاز = یک شاخه + یک گزارش تحویل + توقف تا تایید.** بدون فایل `docs/review/phase-N-APPROVED.md` وارد فاز بعد نشو.
8. اسرار (FTP، رمز ادمین، کلید) هرگز در ریپو؛ فقط `.env.local` محلی ignore‌شده. اسرار را در هیچ گزارش/لاگ/کامنت/commit چاپ نکن.

### ۰.۱ محیط کار و دسترسی FTP
سایتِ فعلی (bagllet.ir) **خودش staging ماست**؛ سرور جدا نداریم. دسترسی FTP همین سایت به تو داده می‌شود (در `.env.local`: `FTP_HOST FTP_USER FTP_PASS FTP_ROOT`). چون Woodmart فعال است و سایت در حال کار، قواعد ایمنی سخت‌اند:
- **خواندن آزاد، نوشتن محدود.** دانلود هر فایلی برای اندازه‌گیری/استخراج مجاز است. آپلود فقط در این مسیرها: `wp-content/themes/bagllet/`، `wp-content/plugins/bagllet-widgets/`، `wp-content/mu-plugins/bagllet-*.php`.
- **ممنوع:** تغییر/حذف Woodmart، المنتور، ووکامرس، سایر افزونه‌ها، `wp-config.php`، `uploads/`، دیتابیس؛ هر عملیات `DELETE`/rename روی FTP؛ **فعال‌کردن قالب جدید** (سوییچ فقط در فاز ۹ و فقط با دستور صریح مدیر).
- **پشتیبان قبل از بازنویسی:** قبل از جایگزینی هر فایل موجود روی سرور، نسخه‌ی فعلی را در `qa/backups/` (ignore) ذخیره کن.
- **دیتابیس از طریق FTP خوانده نمی‌شود.** برای استخراج تنظیمات Woodmart/Header Builder/دیتای المنتور/HTML Blocks/term-meta از **mu-plugin صادرات فقط‌خواندنی موقت** (`bagllet-export.php`: فقط `manage_options`، nonce، فقط خروجی JSON، بدون نوشتن) استفاده کن؛ پس از استخراج **حذفش کن** (آپلود/حذف این یک فایل با اطلاع مدیر). جایگزین: مدیر خروجی را از پنل بگیرد.
- **پیش‌نمایش بدون تاثیر روی بازدیدکننده:** قالب جدید فعال نمی‌شود؛ با mu-plugin پیش‌نمایش (`bagllet-preview.php`، فاز ۲) فقط درخواست‌هایی که کلید مخفی دارند قالب جدید را می‌بینند.
- ایجنت‌ها/ابزارها را با حساب FTP محدود‌شده (فقط `wp-content`) اجرا کن و رمز در پایان پروژه عوض می‌شود.

## ۱. معماری مقصد

### ۱.۱ ساختار ریپو
```
public_html/wp-content/themes/bagllet/   ← قالب اصلی (چیزی که فروخته می‌شود)
  style.css  functions.php  theme.json  screenshot.png  readme.txt  LICENSE
  /inc/                     ← setup, enqueue, customizer, woocommerce, helpers, tgmpa
  /template-parts/          ← header, footer, loop-card, sections
  /woocommerce/             ← override قالب‌های ووکامرس
  /assets/{css,js,fonts,img,icons}/
  /languages/               ← bagllet.pot (+ fa_IR)
public_html/wp-content/plugins/bagllet-widgets/   ← پلاگین همراه (ویجت‌های المنتور، صفحات درباره/تماس؛ فعلاً سر جایش بماند)
public_html/wp-content/mu-plugins/bagllet-preview.php   ← فقط توسعه؛ در zip فروش نمی‌آید
/tools/                     ← deploy امن FTP، اسکریپت‌های کمکی (بدون اسرار)
/qa/                        ← Playwright، baseline، اسکریپت‌های diff، چک‌لیست‌ها
/docs/                      ← این نقشه، handoff، review، دستورالعمل خریدار
```
نام‌گذاری موقت: slug و text-domain `bagllet`، prefix توابع/ثابت‌ها `bagllet_` / `BAGLLET_`. (تغییر نام تجاری قبل از فاز ۱۰ ممکن است؛ همه‌ی prefix ها را متمرکز نگه دار تا قابل جایگزینی باشد.)

### ۱.۲ تصمیم‌های معماری (پیش‌فرض‌ها؛ مدیر می‌تواند تغییر دهد)
- **قالب کلاسیک (PHP) + `theme.json`** برای توکن‌ها و استایل ادیتور. (قالب بلاکی/FSE با ووکامرس و المنتور و بازار فارسی ریسک سازگاری دارد.)
- **بدون build سنگین:** CSS/JS ساده و ماژولار، با اسکریپت اختیاری minify برای release. (کاهش ریسک برای خریدار و بازبینی.)
- **شخصی‌سازی با Customizer بومی وردپرس** (با selective refresh)؛ بدون فریم‌ورک گزینه‌ی خارجی.
- **وابستگی‌ها** با TGM Plugin Activation (GPL): ووکامرس (الزامی)، پلاگین همراه (الزامی)، المنتور (توصیه‌شده برای صفحه اصلی).
- **قابلیت‌های جایگزین Woodmart** (ویش‌لیست، مقایسه، quick view، swatch ویژگی‌ها، جستجوی ایجکس، mini-cart، sticky add-to-cart، زوم/لایت‌باکس گالری...) فقط اگر در فاز ۱ ثابت شد در سایت **استفاده می‌شوند**، پیاده‌سازی شوند — سبک، داخل قالب یا پلاگین همراه.

### ۱.۳ فونت
سایت فعلی از IRANYekan استفاده می‌کند که فونت تجاری است و **نباید داخل بسته‌ی فروش** باشد. رویکرد:
- بسته‌ی فروش: `Vazirmatn` (OFL، قابل‌توزیع) به‌عنوان پیش‌فرض.
- سایت bagllet.ir: IRANYekan از طریق گزینه‌ی «آپلود فونت سفارشی» (Customizer) با `@font-face` پویا لود می‌شود تا ظاهر فعلی عیناً حفظ شود.
- parity فقط روی سایت bagllet.ir (با IRANYekan) سنجیده می‌شود.

## ۲. ورودی‌هایی که از مدیر پروژه لازم است (فاز ۰/۱ را بدون آن‌ها شروع نکن)
همه‌ی موارد زیر **توسط خود ایجنت** از طریق FTP/سایت استخراج می‌شود؛ فقط آنچه در FTP نیست از مدیر خواسته شود.
1. **دسترسی FTP** سایت (`.env.local`) — مدیر می‌دهد. آدرس سایت: bagllet.ir (خودش staging است، بخش ۰.۱).
2. **ورود به سایت:** یوزر/پسورد به ایجنت داده نمی‌شود. مدیر در **مرورگر داخلی Cursor** لاگین کرده است؛ صفحات احرازهویت‌شده (حساب کاربری، تسویه) با همان مرورگر دیده و مدرکشان commit می‌شود. Playwright از آن نشست استفاده نمی‌کند؛ اگر diff خودکار این صفحه‌ها لازم شد، یک‌بار `npm run qa:login` مرورگر را headed باز می‌کند تا مدیر دستی لاگین کند و نشست در `qa/.auth/` (ignore) ذخیره شود. حساب لاگین‌شده ممکن است ادمین باشد: **فقط نگاه کن**؛ هیچ تنظیمی در پنل تغییر نده، هیچ سفارش واقعی ثبت نکن (درگاه باید تست باشد). رمز یا کوکی نشست را هرگز چاپ/ذخیره/commit نکن.
3. **از FTP:** فایل‌های قالب Woodmart و child theme، لیست و نسخه‌ی افزونه‌ها، `wp-content/uploads` (فقط ساختار/فهرست)، نسخه‌ی PHP/WP/Woo (از فایل‌ها یا `site-health` ادمین).
4. **از دیتابیس (با mu-plugin صادرات موقت، بخش ۰.۱):** تنظیمات Woodmart، Header Builder، قالب‌ها/صفحات Elementor، HTML Blocks، term-meta ویژگی‌ها (swatch)، منو-متا (مگامنو).
5. **از مدیر (در صورت نبود در سایت):** فایل SVG لوگوی رسمی و تصمیم‌های باز (breakpoint موبایل، رنگ هدر) — تا خود سایت چیز دیگری نشان ندهد، **رفتار فعلی سایت** معیار است.

## ۳. فازها

هر فاز: **هدف ← کارها ← تحویلی‌ها ← معیار پذیرش (DoD)**. شاخه: `phase/N-نام`.

### فاز ۰ — ایمنی ریپو و ساختار
- **کارها:** بررسی `.gitignore` (اسرار بیرون)، حذف هر رمز از تاریخچه (قبل از اولین push)، ساخت ساختار پوشه‌ها (بخش ۱.۱)، `README.md`، `.editorconfig`، `.gitattributes` (LF)، `docs/PROGRESS.md`، `docs/LICENSES.md` (خالی)، `docs/PARITY-EXCEPTIONS.md` (خالی).
- **DoD:** `git grep -n -i -E "pass(word)?\s*[=:]|ftp_pass|secret|api[_-]?key"` هیچ مقدار واقعی نشان ندهد؛ ریپو **خصوصی** است؛ ساختار ایجاد شده.

### فاز ۱ — خط پایه (Baseline) و فهرست قابلیت‌ها  ← مهم‌ترین فاز
هدف: «ظاهر فعلی» را به داده تبدیل کن تا هر فاز بعدی با ماشین سنجیده شود.
- **۱.الف فهرست صفحات و حالت‌ها** (`docs/inventory/pages.md`): از sitemap و صفحات ووکامرس؛ حداقل: اصلی، درباره، تماس، فروشگاه، دسته (چند نوع)، محصول (ساده/متغیر/ناموجود/تخفیف‌دار/گالری‌دار)، سبد (خالی/پر)، تسویه، تشکر، حساب کاربری (ورود/ثبت‌نام/داشبورد/سفارش‌ها/آدرس‌ها/جزئیات)، وبلاگ (آرشیو/تک‌نوشته)، جستجو (نتیجه/بدون نتیجه)، ۴۰۴، ویش‌لیست/مقایسه (اگر هست)، صفحات قانونی.
- **۱.ب حالت‌های تعاملی:** hover/focus/active دکمه‌ها و کارت‌ها، منوی دراپ‌داون/مگامنو، منوی موبایل، mini-cart باز، جستجوی باز، quick view، پاپ‌آپ‌ها، sticky header در اسکرول، sticky add-to-cart، خطاهای فرم، اعلان‌های ووکامرس، حالت loading.
- **۱.ج ضبط خط پایه** (`qa/` با Playwright): اسکرین‌شات تمام‌صفحه در عرض‌های **1440، 768، 390** + برش‌های header/footer در ۱۲۸۰ و ۱۰۲۴؛ ماسک‌کردن بخش‌های پویا (اسلایدر، اینستاگرام، ساعت/تاریخ). خروجی در `qa/baseline/<page>/<width>.png`.
- **۱.د استخراج مشخصات:** برای هر المان کلیدی (هدر، منو، دکمه‌ها، کارت، تگ، فرم‌ها، تیترها، فوتر...) یک JSON از computed style (font، size، line-height، color، padding، margin، border، radius، shadow، transition، z-index) و bounding box در هر breakpoint → `qa/baseline/specs/*.json`. breakpoint های واقعی را از media query های زنده اندازه بگیر (فقط مشاهده).
- **۱.ه فهرست قابلیت‌ها و وابستگی‌ها** (`docs/inventory/features.md`): هر ویژگی Woodmart که **واقعاً** در سایت دیده می‌شود (header builder، mega menu، swatch، quick view، wishlist، compare، ایجکس search، sticky ATC، گالری، فیلترها، لودمور/صفحه‌بندی، popup، cookie bar…)، هر **ویجت/شورت‌کد Woodmart داخل دیتای المنتور و HTML Blocks**، هر CPT/متای Woodmart (`cms_block`, `woodmart_layout`, term-meta برای swatch، منو-متا برای مگامنو)، و **نقشه‌ی مهاجرت داده** برای هرکدام (چه چیزی باید منتقل/جایگزین شود).
- **۱.و فهرست افزونه‌ها** و ارتباط هرکدام با ظاهر (hook ها/ایجاد DOM).
- **۱.ز دسترسی و استخراج:** تایید اتصال FTP (فقط خواندن)، دانلود فایل‌های لازم، استخراج دیتابیس با mu-plugin موقت (بخش ۰.۱) و حذف آن در پایان؛ نتایج خام در `qa/data/` (ignore اگر حساس است) و خلاصه در `docs/inventory/`.
- **DoD:** baseline برای ≥ ۹۵٪ صفحات/حالت‌های فهرست‌شده موجود؛ JSON مشخصات؛ سه سند inventory کامل؛ اسکریپت `npm run qa:baseline` قابل اجرای مجدد؛ **هیچ فایلی روی سایت تغییر نکرده** جز نصب و حذف mu-plugin صادرات (با ثبت در handoff).

### فاز ۲ — اسکلت قالب، توکن‌ها، ابزار QA
- قالب خالی ولی معتبر در `public_html/wp-content/themes/bagllet/` (هدر style.css کامل، `functions.php` ماژولار، `theme.json` با پالت/تایپوگرافی/اسپیسینگ از شناسنامه، `add_theme_support` ها، منوها، sidebar ها، `screenshot.png` موقت).
- `assets/css/tokens.css` (همه‌ی متغیرها: رنگ، فونت، مقیاس تایپ 56/80…، radius 6/8/10/12، فواصل پایه ۴px، کانتینر 1280، گرید ۴ستونه gap 24) + `base.css` (reset، تایپوگرافی، فوکوس مشکی/Clay، RTL).
- فونت: `@font-face` پویا (آپلود سفارشی) + Vazirmatn bundled؛ letter-spacing 0؛ اعداد فارسی.
- **ابزار QA:** `qa/diff` (pixelmatch/Playwright) که خروجی قالب جدید را با baseline مقایسه می‌کند؛ `qa/checks` (grep ممنوعه‌ها: `wd-|xts-|woodmart`، hex های خارج از tokens، `!important` بدون کامنت)؛ `phpcs.xml` (WPCS)؛ `package.json` با اسکریپت‌ها.
- **ابزارها:** اگر Node LTS، PHP (۸٫۱+) یا Composer نصب نیست، خودت از ترمینال نصب کن (مثلاً `winget`) و نسخه‌ها را در `README.md` ثبت کن. فقط همین ابزارهای توسعه؛ تغییر دیگری در تنظیمات سیستم نده.
- **deploy امن:** `tools/deploy.ps1` (یا معادل Node) که فقط مسیرهای مجاز بخش ۰.۱ را آپلود کند، قبل از بازنویسی از فایل سرور پشتیبان بگیرد، `DELETE` نداشته باشد، حالت `-DryRun` داشته باشد و اسرار را فقط از `.env.local` بخواند.
- **پیش‌نمایش:** mu-plugin `bagllet-preview.php`: وقتی کوکی/پارامتر با کلید مخفی (ثابت در `wp-config` نه در ریپو؛ کوکی HttpOnly) موجود است، با فیلترهای `template`/`stylesheet`/`option_template`/`option_stylesheet` قالب `bagllet` اعمال شود؛ برای بقیه‌ی بازدیدکنندگان هیچ تغییری نکند. در حالت پیش‌نمایش، CSS/JS قدیمیِ پلاگین که برای Woodmart نوشته شده (`site-theme.css`، `assets/footer/*`) **بارگذاری نشود** تا parity آلوده نشود؛ هرچه از آن‌ها لازم است به قالب منتقل می‌شود (فازهای ۳ تا ۷).
- **DoD:** قالب روی وردپرس تمیز بدون notice/warning در حالت پیش‌نمایش کار می‌کند؛ بازدیدکننده‌ی عادی همچنان Woodmart را می‌بیند؛ `phpcs` بدون error؛ چک ممنوعه‌ها صفر؛ اسکریپت diff اجرا و گزارش می‌دهد.

### فاز ۳ — هدر، فوتر، ناوبری سراسری
- هدر دسکتاپ/موبایل/sticky، لوگو، منو + دراپ‌داون/مگامنو (مطابق inventory)، جستجو، آیکن‌های حساب/سبد/ویش‌لیست، top bar، drawer موبایل، breadcrumb، scroll-to-top، فوتر کامل (ستون‌ها، تماس، شبکه‌های اجتماعی، نمادهای اعتماد، کپی‌رایت).
- کدِ فعلی پلاگین (`includes/footer.php`، `assets/footer/*`، `site-theme.css`) **مرجع رفتار** است؛ منطق را به قالب منتقل و تمیز کن، نه اینکه کپی بی‌فکر.
- هر چیز قابل‌شخصی‌سازی را از ابتدا با `get_theme_mod()` + مقدار پیش‌فرض مساوی سایت فعلی بنویس (مثلاً لینک‌های فوتر، متن‌ها، سوشال‌ها).
- **DoD:** diff هدر/فوتر در ۱۴۴۰/۷۶۸/۳۹۰ در آستانه‌ی بخش ۵؛ تمام حالت‌های تعاملی ۱.ب برای هدر/فوتر؛ کیبورد و ARIA؛ بدون JS غیرضروری؛ بدون Elementor کار می‌کند.

### فاز ۴ — صفحات محتوایی

## ۵. فهرست چک‌های خودکار (اجرا قبل از هر push)
```
php -l روی همه‌ی فایل‌های تغییرکرده
phpcs --standard=phpcs.xml
git grep -n -i -E "wd-|xts-|woodmart" -- public_html/wp-content  → باید خالی باشد
git grep -n -E "#[0-9a-fA-F]{3,8}\b" -- public_html/wp-content/themes/bagllet/assets/css | بجز tokens.css → خالی
git grep -n "!important" → هر مورد کامنت دلیل داشته باشد
npm run qa:diff -- --phase N  → آستانه‌ها
```
**آستانه‌ی diff:** درصد پیکسل متفاوت ≤ ۰٫۳٪ در هر صفحه/عرض (پس از ماسک پویاها)؛ bounding box المان‌های کلیدی ±۱px؛ CLS صفر؛ هر مورد بالاتر باید رفع یا در `PARITY-EXCEPTIONS.md` تایید شود.

### ۵.۱ راستی‌آزمایی بصری با مرورگر داخلی Cursor (تکمیل‌کننده‌ی diff خودکار)
مرورگر داخلی برای دیدن و تست تعاملی است، **جایگزین diff عددی نیست** (چشم، ۱px یا تفاوت رنگ کم را نمی‌بیند). هر فاز هر دو را انجام دهد:
1. صفحه‌های فاز را با کلید پیش‌نمایش (بخش ۰.۱) در مرورگر داخلی باز کن و کنار نسخه‌ی Woodmart (بدون کلید) در سه عرض 1440/768/390 مقایسه کن.
2. حالت‌های تعاملی همان فاز را دستی اجرا کن: hover/focus/active، منوها، drawer موبایل، mini-cart، جستجو، sticky، فرم‌ها و خطاها، افزودن به سبد (AJAX).
3. کنسول مرورگر: **صفر خطای JS و صفر هشدار مهم**؛ تب Network: صفر 404/۵۰۰ و بدون فایل Woodmart (`wd-`/`woodmart`) لودشده در حالت پیش‌نمایش.
4. با `getComputedStyle` مقادیر المان‌های کلیدی را با `qa/baseline/specs/*.json` مقایسه کن (فونت، اندازه، رنگ، padding، radius، فاصله)؛ اختلاف = باگ.
5. کیبورد: Tab روی همه‌ی المان‌های تعاملی، فوکوس‌رینگ دیده شود (مشکی روی روشن/Clay روی مشکی)؛ تغییر اندازه‌ی پنجره بین breakpoint ها بدون پرش layout.
6. **مدرک باید commit شود** (وگرنه ناظر نمی‌بیند): در `docs/handoff/evidence/phase-N/` برای هر صفحه‌ی تغییرکرده یک تصویر کنار‌هم (قدیم | جدید) در هر سه عرض، WebP فشرده (هر فایل ≤ ۳۰۰KB)، به‌علاوه‌ی `console-network.md` با خلاصه‌ی خطاها. «در مرورگر دیدم درست است» بدون مدرک پذیرفته نیست.
